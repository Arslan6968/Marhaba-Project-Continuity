# Contributing

Thanks for helping improve Marhaba Project Continuity.

## Useful contributions

- Reproducible evaluation scenarios showing a practical failure or improvement.
- Clearer instructions that reduce unnecessary questions or work.
- Cross-agent compatibility observations with product/version details.
- Focused changes to templates, verification rules, and release guidance.
- Fixes to the structural validation script.

## Before opening a pull request

1. Explain the problem and the intended behavior change.
2. Keep changes scoped; avoid adding process or documentation that has no demonstrated value.
3. Run `python scripts/validate_skill.py`.
4. If changing behavior guidance, update or add an evaluation scenario and expected behavior.
5. Never include credentials, private project files, personal data, or customer information.
6. Distinguish verified results from assumptions and untested expectations.

## Design principles

- Portable instructions before vendor-specific assumptions.
- Evidence before confident claims.
- Small reversible changes before broad rewrites.
- Risk-scaled caution, not needless ceremony for every task.
- Continuity notes only when they improve future work.
- Honest limits; no claims of universal compatibility or guaranteed correctness.

By contributing, you agree that your contributions may be distributed under the repository's MIT License. Do not submit material you do not have the right to contribute.
